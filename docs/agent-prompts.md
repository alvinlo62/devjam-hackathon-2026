# Agent 分階段 Prompt

搭配 `docs/spec.md` 使用。**一次只貼一個階段，驗收完再進下一步。**

不要一次貼完整份規格書——那樣 agent 會一路做到底，你就量不出自己會卡在哪裡。

---

## 階段零：載入上下文

```
請先讀 AGENTS.md、README.md、docs/spec.md，然後只回答我三件事：

1. 用兩句話說明 ai/ 和 services/ 的職責界線
2. 這個演練的模擬題目要做什麼
3. 你認為規格裡最容易出錯或最模糊的地方是什麼

先不要寫任何程式碼。
```

**為什麼要這一步**：確認它真的讀懂架構鐵則。第 3 題的答案通常會提前暴露規格漏洞。

---

## 階段一：介面契約（20 分鐘）

```
執行 docs/spec.md 的「階段一：介面契約」。

只改 backend/models.py 和 docs/api.md，不要碰任何其他檔案，
不要寫任何業務邏輯。

完成後回報：
- models.py 的完整內容
- uv run python -c "import models" 的執行結果
- 你對規格做的任何補充假設

然後停下來等我確認。
```

---

## 階段二：規則引擎（50 分鐘）

```
執行 docs/spec.md 的「階段二：規則引擎」。

只改 backend/services/ 和 backend/tests/。

硬性要求：
- services/ 內不得 import ai，不得呼叫任何外部 API
- 所有判定函式必須是純函式
- 規格列出的四個測試案例全部要寫

完成後回報：
- uv run pytest 的實際輸出
- grep -rn "import ai" backend/services/ 的實際輸出（應為空）

然後停下來等我確認。
```

---

## 階段三之一：先做 fixture（15 分鐘）

```
執行 docs/spec.md 的「階段三 3-1」。

只做 fixture，還不要接真實 API。

要求：
- 依規格建立 A / B / C 三組測試資料
- B 組是主要 Demo 素材，必須包含兩組重疊訂閱
- DEMO_MODE=true 時，整條 /api/analyze 流程要能跑完，完全不需網路

完成後回報：
- DEMO_MODE=true 時實際呼叫 API 的完整回應 JSON

然後停下來等我確認。
```

**這一步不能跟 3-2 合併。** 先有離線可跑的版本，才有本錢去接會失敗的外部 API。

---

## 階段三之二：接真實 API（45 分鐘）

```
執行 docs/spec.md 的「階段三 3-2」。

改 ai/prompts/*.md 和 ai/tasks/*.py。

注意：ai/client.py 裡的 Gemini SDK 寫法我尚未驗證過，
若與官方文件不符請直接指出，不要自行猜測參數名稱。

要求：
- prompt 存在 .md 檔，用標題與清單分段，不要寫死在 Python 裡
- 抽取失敗時要能降級到 fixture，不可讓流程中斷

完成後回報：
- 用真實帳單文字跑通的結果
- 用圖片輸入跑通的結果
- 故意傳一段無意義文字時的行為

然後停下來等我確認。
```

---

## 階段四：前端（50 分鐘）

```
執行 docs/spec.md 的「階段四」的前端部分。

只改 frontend/src/。

要求：
- 年度總支出、可節省金額為視覺重點
- 依 status 用不同顏色標示（keep / review / redundant）
- API 失敗時要顯示錯誤訊息，不可白畫面
- 不要引入任何新的前端套件

完成後回報改動的檔案清單。然後停下來等我確認。
```

**斷網演練是你自己做的，不要交給 agent。** 你要練的就是「發現異常 → 判斷原因 → 切 DEMO_MODE」這個反應。

---

## 階段五：Demo 收尾（40 分鐘）

```
依 docs/demo-script.md 的表格結構，用 B 組 fixture 填寫一份完整的 Demo 腳本。

包含每一步的操作、預期畫面、以及該講的重點。
主線必須演到「重疊偵測」和「可省金額」這兩個亮點。

不要寫程式碼，只寫腳本。
```

**錄影和排練不能交給 agent。** 這兩件事沒有人替你做。

---

## 給 agent 的追問模板

進行中如果覺得它偏離方向，這幾句很好用：

| 情況 | 說法 |
|---|---|
| 它自己加了東西 | 「AGENTS.md 的『刻意不做的事』有列到這項嗎？沒有的話請移除。」 |
| 判定邏輯疑似跑進 AI | 「這個分數是誰算的？如果是 AI 算的，請搬到 services/。」 |
| 它想改 models.py | 「models.py 是契約，改動前請先說明為什麼非改不可。」 |
| 它一次做太多 | 「請只完成當前階段，其餘的等我確認後再說。」 |
| 它宣稱完成 | 「請貼出驗證指令的實際輸出，不要只說通過。」 |

---

## 演練時要觀察的事

跑完之後，除了規格書裡的檢討表，另外記錄：

- [ ] 哪幾次是 agent 誤解規格？→ 代表你的規格寫得不夠明確
- [ ] 哪幾次你必須介入修正架構？→ 代表 AGENTS.md 要補規則
- [ ] 你「檢查它的產出」花了多少時間？→ 這在真實比賽會被低估
- [ ] 有沒有一段時間你完全在等它？→ 那段時間本來可以做簡報

最後一項最重要。用 agent 的真正瓶頸通常不是它寫得慢，而是**你變成單線程的審核者**。
